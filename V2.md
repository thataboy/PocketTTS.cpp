# Pocket TTS v2

The `v2` branch builds on `mine` with multilingual models and the CPU gains
validated in `experimental`: split FP32 KV storage, valid-prefix attention,
strided attention products, and phase-convolution decoding. INT8 and a maximum
decoder chunk of four frames are the defaults. Legacy models still work.

## Build and run

The normal CMake build includes the native C++ JSON tokenizer. It uses the
existing JSON header and adds no build dependency. Python is only needed for
export or reference validation; Cargo and Rust are not needed.

```sh
cmake -S . -B .build -DCMAKE_BUILD_TYPE=Release
cmake --build .build -j4
./ptts --models-dir models-v2 --language english "Hello, world." narrator output.wav
./ptts --models-dir models-v2 --language french "Bonjour le monde." narrator output.wav
```

A direct bundle directory also works (`--models-dir models-v2/english`). Use
`--precision fp32` to select FP32. A legacy directory containing `tokenizer.model`
selects the v1 interface automatically. Existing server options are unchanged.
`--inspect-text "text"` prints v2's prepared chunks and tokenizer IDs.

For Android, use the existing NDK build instructions. JSON tokenization now
cross-compiles as ordinary C++ and needs no Rust target or Cargo linker. Keep
`-O3`: fast-math can break the NaN sentinels used for model defaults and the BOS
latent. A legacy-only build can disable JSON tokenization with
`-DPOCKET_JSON_TOKENIZER=OFF`.

## Export

Use the Python environment in `requirements-export-v2.txt` and install the
upstream `pocket3` checkout at the revision pinned in `export_onnx_v2.py`.

```sh
python export_onnx_v2.py --source ../pocket3 --language english --output-dir models-v2/english
python export_onnx_v2.py --source ../pocket3 --language french --output-dir models-v2/french
```

One command exports FP32 and INT8, applies both retained CPU graph rewrites,
validates their outputs, and writes the bundle manifest. `--fp32-only` skips
INT8. The decoder remains FP32 in both precision modes. Existing bundles remain
usable. To pick up upstream checkpoint fixes, export a new bundle; updating the
binary alone does not change the weights.

### October 2026 English checkpoint

The exporter pins pocket3 `a922b912dfa366975294afb568d815b305acde5d`
(v4.0.1). Default `english` now selects `english_2026-10`, retrained to fix the
training-data truncation that caused sentence-final years/numbers and following
words to disappear ([upstream issue #395](https://github.com/kyutai-labs/pocket-tts/issues/395)).
Its config also converts curly apostrophes to straight apostrophes. The native
C++ tokenizer already applies these config replacements; no runtime rebuild or
number-to-words workaround is required.

Keep the previous bundle for comparison and export to a new directory:

```sh
python export_onnx_v2.py --source ../pocket3 --language english --output-dir models-v2-2026-10/english
./ptts --models-dir models-v2-2026-10 --language english "She was born in New York in 1943. Her father was a Hungarian Jewish immigrant." narrator output.wav
```

The bundle includes FP32/INT8 and the same CPU optimizations. French weights
are unchanged; a fresh French export also picks up the new en-dash-to-comma
replacement in its config. The new upstream 2M/7M/18M variants use different model interfaces
and are not supported by this exporter.

Validated on M1 CPU on 2026-10-21:

- Both language exports passed 360 independent component checks, INT8 checks,
  four decoder rewrites, and 57-call bit-exact attention checks per precision.
- All 26,196 native tokenizer checks passed with the new bundle configs.
- The original Glück passage and the shorter two-sentence year reproduction
  retain `1943`, `her father`, and `Hungarian` in all 12 large-v3 ASR transcripts
  (Python, native FP32, native INT8; temperature zero and default 0.3; narrator,
  seed 42). At temperature zero, native FP32 matches Python at 51.5/61.8 dB SNR.
- French FP32/INT8 streamed WAVs are byte-identical to the previous bundle for
  the control sentence without an en dash. Named-cache refresh checks pass.
- Alternating old/new English INT8 CLI runs, discarding the first pair, measured
  aggregate RTFX 8.54x/8.62x and median TTFA 350/348 ms. Five retained pairs used
  AR1/decoder3, chunk four, temperature zero, seed 42 and disabled disk caches;
  TTFA includes voice encoding. This shows no measurable speed regression and
  does not establish Android performance.

Local waveforms, transcripts and timing reports are in
`.cache/year-fix-2026-10/`; export reports are inside the new bundles.

To optimize an existing unoptimized split-cache v2 bundle:

```sh
python export_onnx_v2.py --optimize-from models-v2-fast/english --output-dir models-v2/english
```

`--quantize-from BUNDLE` adds validated INT8 to an existing FP32 bundle and
applies the same optimizations. Outputs must be new directories. The original
legacy exporter `export_onnx.py` is retained for v1 models.

## Named voice caches

V2 disk caches use readable paths, for example:

```text
voices/.cache/v2/english/int8/narrator.emb
voices/.cache/v2/english/int8/narrator.kv
voices/.cache/v2/french/int8/narrator.emb
```

Cache freshness uses the voice WAV and model/manifest timestamps. There are no
model-content or voice-content hashes. Use distinct voice filenames within a
voice directory. Replacing a voice reloads its resident embedding on the next
request when its modification timestamp changes. `--no-cache` disables disk
caching; `--refresh-cache` retains its existing meaning. Previous hashed v2
cache directories are unused and may be deleted.

Named voices reuse the last resident KV snapshot. Caller-owned tensor inputs
are recomputed, so changing a tensor in place cannot reuse stale conditioning.

## Validation

`scripts/test_voice_cache.py` checks named cache hits, timestamp invalidation,
and precision separation. `scripts/validate_milestone.py` and
`scripts/validate_int8.py` retain the upstream audio/tokenizer validation tools.
Exporter validation checks streaming state and numerical equivalence before
publishing optimized graphs.

Fused prefill, single-frame graph experiments, voice LRU caches, profiling
prototypes, and experiment journals are left on `experimental`/its stash. The
Android v2 throughput gap remains a separate investigation.

### Consolidation checks (2026-10-20, M1 CPU)

The normal CMake CLI and shared library build successfully. CLI tests compare
against a preserved executable built from the stashed experimental sources,
using the same ORT library, voice, temperature zero, seed 42, AR1/decoder3 and
chunk four. Disk caching is off for these cold-process tests; TTFA includes voice
encoding. These are CLI timings, not warm server throughput figures.

| Case | Experimental median RTFX | V2 median RTFX |
| --- | ---: | ---: |
| Legacy INT8 | 8.73x | 8.72x |
| English INT8 | 8.59x | 8.56x |
| French INT8 | 8.82x | 8.88x |
| English FP32 | 3.35x | 3.36x |
| French FP32 | 3.84x | 3.86x |

All 36 paired CLI comparisons produced identical streamed WAV bytes. Five pairs
were run per case; French INT8 initially had a slower, variable candidate group
(8.34x versus 8.82x), so it was repeated separately for 11 pairs, producing the
French medians above. These runs show no reproducible throughput regression;
small timing differences should not be interpreted as speedups. The baseline
uses plain O3; the normal candidate CMake build additionally uses the existing
native-CPU/unroll flags.

The combined exporter passed a fresh English FP32/INT8 export, upstream component
validation, four decoder rewrites and 57-call exact attention validation per
precision. Freshly exported optimized INT8 CLI output also matched the existing
v2-kv bundle. Export was run from the local Hugging Face cache in offline mode.
Named cache hits preserve audio, voice/model timestamp changes refresh disk
caches, and FP32/INT8 cache paths remain separate. An in-process check also
confirmed resident KV reuse and correct re-encoding after replacing a voice
with a different WAV and changing its timestamp by one millisecond.

Raw reports and the preserved experimental executable are under
`.cache/v2-consolidation/`. Re-run CLI comparisons with
`scripts/test_cli_regression.py --baseline PATH --voice PATH`.
